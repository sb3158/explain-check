# explain-check

목적: 사용자가 AI 없이 자기 결과물을 설명할 수 있게 만든다.
이 스킬은 사용자 대신 판단하지 않는다. 결정이 필요하면 선택지와 근거를 주고 사용자에게 묻는다.

## 5가지 질문 유형

| 유형 | 묻는 것 | 답 구조 |
|---|---|---|
| Q1 설계 선택 | 핵심 부분에서 어떤 방식을 택했나 | 택한 방식 → 이유 → 대안과의 차이 → 포기한 것 |
| Q2 검증 범위 | 실제로 검증한 것과 가정·미구현·미보장인 것 | 검증한 것(+확인 명령) → 가정한 것 → 미구현 |
| Q3 동작과 예외 | 정상 흐름과 예외 상황별 동작 | 정상 순서 → 예외별 동작 → 기존 데이터가 어떻게 되는지 |
| Q4 가장 약한 지점 | 어떤 입력에서 품질이 무너지나 | 약점 → 무너지는 조건 → AI 설명이 아닌 실측 방법 → 개선 |
| Q5 AI 협업 판단 | AI와 함께 내린 특정 결정 | 계기 → AI 제안 중 수용·수정·버림 → 근거가 된 실행 결과 |

## 공통 규칙

- 실제로 실행해서 확인한 것만 사실로 쓴다. 확인 못 한 것은 `미검증: (확인 방법)`으로 쓴다.
- 근거에는 코드 위치(파일, 함수)와 확인 명령을 함께 적는다.
- 사용자가 그대로 말할 수 있는 쉬운 문장으로, 항목마다 3줄 이내로 쓴다.
- 기록은 프로젝트 루트의 `EXPLAIN.md` 한 파일에만 한다.

## plan 모드: 설계 방향을 정한 직후, 코딩 전 (약 5분)

알고리즘 방향(어떤 방식으로 풀지)만 정해졌으면 부른다. 세부 구현은 몰라도 된다.
구현 도중 알고리즘 방향이 크게 바뀌면 plan을 다시 불러 질문과 테스트를 갱신한다.

1. 현재 설계와 요구사항을 읽고, 이 프로젝트에 맞춘 Q1~Q5 질문을 한 문장씩 만든다.
2. 각 질문에 답하려면 작업 중에 무엇을 남겨야 하는지 정한다.
   - Q1: 비교한 방식 2개와 각각 포기하는 것. 아직 비교하지 않았다면 두 방식을 제안하고 사용자가 고르게 한다. 사용자가 설명할 수 있는 쪽을 권한다.
   - Q3: 예외 상황 목록(빈 입력, 잘못된 데이터, 제약 위반, 후보 없음 등)과 각각의 기대 동작, 실패했을 때 기존 데이터를 지키는 방식.
   - Q4: 약점 가설 1~2개, 그걸 잴 결과 지표 2~3개, 약점을 드러낼 극한 입력.
   - 기준선: 가장 단순한 방식(또는 현재 운영 방식)의 결과 지표를 먼저 측정하자고 제안한다. 이후 알고리즘을 바꿀 때마다 이 값과 비교한다.
3. 예외 테스트와 극한 입력 테스트를 작업 계획의 별도 단계로 넣자고 제안한다.
4. AGENTS.md(없으면 사용자에게 물은 뒤 생성)에 아래 두 줄을 추가한다.
   - 핵심 로직을 바꿀 때는 전후 결과 지표를 표로 보여주고, 유지·되돌림은 사용자가 정한다. 결정은 EXPLAIN.md "결정" 섹션에 계기·수용/수정/버림·근거로 한 줄 기록한다.
   - 예외 상황 테스트는 실제로 실행하고, 결과를 EXPLAIN.md "테스트" 섹션에 기록한다.
5. 결과를 EXPLAIN.md에 아래 형식으로 남긴다.

```
# EXPLAIN
## 준비
- Q1~Q5 질문 (이 프로젝트용)
- 예외 상황 목록과 기대 동작
- 약점 가설, 결과 지표, 극한 입력
## 결정
## 테스트
## 방어 노트
```

## final 모드: 제출 직전 (약 15분)

1. 근거 수집 (5분 이내)
   - 테스트와 실행 명령을 실제로 돌린다.
   - plan에서 정한 예외 상황과 극한 입력 중 아직 안 돌린 것을 빠르게 실행해 "테스트"에 기록한다.
   - 버그를 찾으면 바로 고치지 말고 사용자에게 알리고, 고칠지 물어본다.
2. 방어 노트 (5분)
   - EXPLAIN.md "방어 노트"에 Q1~Q5를 각각 3~5줄로, 위 답 구조대로 쓴다.
   - "결정" 섹션이 비어 있으면 커밋 기록과 대화에서 찾아 쓰고, 근거를 못 찾은 결정은 `미검증`으로 표시한다.
3. 퀴즈 (5분)
   - 유형마다 질문을 하나씩, 한 번에 하나만 낸다. 답은 먼저 보여주지 않는다.
   - 사용자가 답하면 방어 노트와 비교해 빠진 부분만 1~2줄로 짚는다.
4. 마지막으로 사용자가 외워갈 핵심을 유형당 한 줄, 총 5줄로 요약한다.
