# final: 제출 직전

1. **근거**
   - "설계"와 "결정"의 주장마다 근거(명령과 결과)를 "근거" 섹션에 연결한다. 금방 확인할 수 있는 것만 확인하고, 나머지는 미검증으로 둔다.
   - Tiger 대책이 실제로 반영됐는지, "구조"의 파일과 함수가 실제 코드와 맞는지 확인하고 고친다.
   - 커밋 메시지의 `가정:`과, 코드에 단순화와 그 한계를 적은 주석(예: `ponytail:`)을 모아서 "가장 약한 지점"과 "검증 범위"의 재료로 쓴다.
   - AI 설명이 아닌 근거(손계산, 작은 예제로 직접 확인, 다른 방법으로 같은 값 확인 등) 2개를 남긴다.
   - 버그를 찾으면 알리고 고칠지 묻는다 **(결정)**.
2. **방어 노트**: "설명 질문" 6개에 각각 3~5줄로 답한다.
   - 설계 선택: 택한 방식 → 이유 → 대안과 차이 → 포기한 것
   - 구조와 데이터 흐름: 모듈별 역할 → 입력이 결과가 되는 경로(`파일:함수`) → 저장 위치와 바꾸는 주체
   - 검증 범위: 확인한 것(+명령) → 가정한 것 → 미구현
   - 동작과 예외: 정상 순서 → 예외별 동작 → 기존 데이터가 어떻게 되는지
   - 가장 약한 지점: 약점 → 무너지는 조건 → 실측 방법 → 개선
   - AI와 내린 결정: 계기 → 수용·수정·버림 → 근거
3. **퀴즈**: 한 번에 한 문제씩, 답은 먼저 보여주지 않는다. 사용자가 답하면 방어 노트와 비교해 빠진 것만 1~2줄로 짚는다.
4. **요약**: 질문당 한 줄, 총 6줄로 핵심을 정리한다.
